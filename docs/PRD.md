## 1. 项目背景与目标

### 1.1 背景与目标

面向**长租公寓（按月租住）**的轻量运营管理系统，把门店 → 房源 → 租户 → 收款 → 退房全流程搬到线上，解决信息分散、房态不同步、到期遗忘、对账困难的问题。本期定位为**纯内部运营后台**（管理员 + 运营人员使用），租户仅作为内部档案，不开放自助门户。

### 1.2 范围（以 v1.2 实现为准）

- **已实现**：门店、房源、租户（含租期/押金/附件）、收款账单（含水电费）、站内提醒、系统用户、工作台统计、登录鉴权、**操作日志审计**。
- **未实现（v0.4 规划项，详见 §8）**：独立合同模块、报修工单模块、周期性账单自动生成与欠缴跟踪、报表导出、数据备份与恢复界面、门店级 RBAC 隔离、证件号加密。
- **范围外（保持不做）**：租户自助门户 / 小程序、电子发票与税务对接、智能家居 / 门禁联动。

## 2. 用户角色与权限

| 角色 | 系统枚举 | 当前实际能力 |
| ---- | ---- | ---- |
| 系统管理员 | `admin` | 全部功能（含用户管理、改密、**操作日志查询 / 导出**） |
| 店长 / 运营 / 财务 | `manager` / `operator` / `finance` | 其余功能与 admin 相同；**操作日志菜单隐藏、接口 403** |

> ⚠️ 角色枚举与 `store_id` 字段已建，但**门店数据隔离尚未启用**：任一已登录账号仍可访问全部门店数据。v1.2 起「操作日志」是本系统**首个真正启用角色限制**的模块，且后端实时回查数据库里的 `role / status`，不信任 7 天有效期 JWT 里可能已过期的角色。其余接口仍按 v0.4 遗留口径全员可用（§8）。

登录态：JWT（`Authorization: Bearer`），有效期 7 天；路由守卫拦截未登录访问；401 自动清除本地 token 并跳转登录页。

- **退房时间**：退房或把状态改为「已退租」时记录北京时间；恢复在住则清空；列表 / 卡片展示。

- 新建入住且月租 > 0 时，后端**自动生成一笔「入住首期房租」收款单**（收款时间 = 实际录入当天、含时分秒；记录房租起止区间，见 §4.1）。

### 3.5 收费账单（`/billing`）

- 两端一致：按月份 / 门店 / 单号·租户·房号筛选；收款笔数、合计金额、按门店小计。

### 3.9 基础设施

- 登录 / 登出 / 获取当前用户 / 改密；路由守卫；统一请求封装自动附带 JWT；**登录页不预填任何账号密码**。
- 前后端统一北京时间（UTC+8），所有 `created_at` / `paid_at` / `check_out_date` / 抄表日期 / `audit_logs.ts` 口径一致。
- 附件读取需 JWT；前端用 `fetch + Bearer` 取回转成 `blob:` URL，按 url 缓存、切换账号 / 登出 / 401 时释放。
- 请求错误由 axios 响应拦截器统一提示；`main.js` 对未捕获的请求异常做 `unhandledrejection` 兜底。
- 部署脚本幂等生成随机 `JWT_SECRET`、收敛宽松 CORS、排除同步 `server/.env`（§7）。

## 4. 核心业务流程（对齐实际实现）

### 4.1 办理入住

1. 工作台「办理新入住」跳转 `/tenant?create=1` 并自动打开新增表单。
2. 选门店 → 选房间（自动带出押金 / 月租）→ 填入住日（自动算房租到期日）→ 上传证件与合同照片（前端压缩）。
3. 保存：后端创建租户 → `syncRoomStatus` 把房间置 `rented` → 若月租 > 0，**自动生成「入住首期房租」收款单**：
   - `paid_at` = **实际录入当天**（北京时间，含时分秒），不取历史入住日；
   - `rent_old_due` = 入住日，`rent_new_due` = 房租到期日（账单据此显示到期日与起止区间）。
4. 结果：房间「已租」、房源页显示当前在住人、账单出现首期收款记录。

> 历史缺陷已修（2026-11-03）：旧逻辑把首期收款时间写成入住日、且未存 `rent_new_due`，导致账单显示 2026-04-03、房租到期日空白。

### 4.2 房租收缴（工作台「当前在住」→ 房租收缴）

1. 弹窗带出住户、房间、本期到期日、月租、上次水电读数与门店单价；默认延期日 = `max(本期到期日, 今天) + 1 个自然月`。
2. **水费、电费各自独立**选择计费方式（三选一）：`不计` / `按抄表` / `包月`。可「水包月 + 电抄表」混合。
   - 按抄表：费用 = `max(0, 本次读数 − 上次读数) × 单价`；单价手填优先，缺省回落门店单价。
   - 包月：直接手填金额。
   - 前端实时展示算式与合计；校验读数不得小于上次读数。
3. 提交走**原子接口** `POST /tenants/:id/collect`：一次完成「生成收款记录 + 顺延房租到期日 + 推进水电表读数」，避免半截数据。
4. 读数推进规则：**只推进选了「按抄表」的那一项**，另一项保持不动；抄表日期更新为本次收款日。

### 4.3 退房

1. 「当前在住」点「退房」→ 二次确认。
2. 后端 `POST /tenants/:id/checkout`：租户置 `left` + 记录 `check_out_date`（北京时间）→ 房间置 `cleaning`（**待清扫**），不调用 `syncRoomStatus`（否则会因无在住租户被误判为空置）。
3. 该租户从「当前在住」消失；房源页该房间「待清扫」、在住人清空。
4. 保洁完成后由管理员在房源页手动改为「空置」。

> 退房目前只做状态流转，不涉及押金退还 / 水电结清 / 退房备注；历史账单全部保留。

### 4.4 附件

上传（前端压缩）→ multer 落盘 `uploads/tenants/:id/` → 元数据写入 `tenants.attachments` JSON。

**读取（v1.1 起需鉴权）**：`GET /api/uploads/tenants/:id/:filename` 挂 `authRequired`，返回 `Cache-Control: no-store` + 白名单图片 Content-Type + `X-Content-Type-Options: nosniff`。由于 `<img src>` / `a-image` / `showImagePreview` 都无法携带 Authorization 头，前端统一通过 `src/utils/authImage.js` 用 `fetch + Bearer` 取回 Blob、转成同源 `blob:` URL 再交给展示组件：

- 只在打开「查看附件 / 编辑租户 / 全屏预览」时按需拉取，列表不预下载身份证照片；
- 同一 url 全局缓存 + 并发去重；登录 / 登出 / 401 时 `revokeObjectURL` 清空，避免 PII 跨会话残留；
- token 只在请求头，不进入 URL、nginx 访问日志或 Referer。

上传与删除同样需登录，扩展名强制收敛为图片白名单。

### 4.5 操作日志采集（v1.2）

`express.json()` 之后、所有 `/api` 路由之前挂 `auditMiddleware`：包装 `res.json` 留一份响应摘要，在 `res` 的 `finish` 事件里按「方法 + 路径 → 模块 / 动作」映射落一条 `audit_logs`。业务路由通过 `setAuditDetail(req, {...})` 补充旧值 / 单号，与中间件合并为**同一条**日志（一次请求只写一条）。

- 字段：时间（北京时间）、操作人 / 角色、模块 / 动作、目标 ID 与对象名快照、请求方法 / 路径、IP（`X-Forwarded-For` 首段）、UA、成功 / 失败与状态码、脱敏明细 JSON、请求 ID。
- 脱敏：`password` / `token` / `authorization` / `idCard` 等一律写 `***`；`attachments` 只记张数；明细上限 4KB，超限只保留业务埋点。
- 关键埋点：`payments` 新增 / 删除（删除前留存单号、金额、收款时间、房租起止、水电费）、`tenants` 入住首期单号 / 编辑 / 删除 / 改到期日（改前→改后）/ 收款（单号、金额、旧→新到期日、水电模式）/ 退房（状态与退房时间）。
- 审计基线：首次启动写一条 `enable_audit`，界面展示该时间点；**启用前的历史操作不补录、不倒推**。
- 保留策略：`AUDIT_RETENTION_DAYS`（默认 180，0 = 永久）按北京时间每日清理一次，基线记录永久保留，清理动作本身也写日志。日志**不提供删除接口**，避免抹痕。
- 权限：`/api/audit/*` 挂 `authRequired` + 路由内实时回查 `users.role/status`，仅 `admin` 可查询与导出；菜单对非 admin 隐藏。

## 5. 实际数据模型

> ⚠️ 与 v0.4 规划不同：**未建** `Building` / `Lease` / `Bill` / `WorkOrder` 表。租期与押金内联在 `tenants`，收款为 `payments` 单表记账（无独立账单表）。以下为实际 8 张表。

| 表 | 关键字段 | 说明 |
| ---- | ---- | ---- |
| `users` | id, username, password_hash, name, role, store_id, status, created_at | 系统账号；`status=disabled` 表示禁用 |
| `stores` | id, code, name, address, manager, phone, status, **water_price, electricity_price**, created_at | 门店；水电单价为计费缺省值 |
| `rooms` | id, store_id, room_no, floor, area, type, rent, deposit, status, **water_meter, electricity_meter, meter_date**, created_at | 房源；`status` 含 `cleaning` |
| `tenants` | id, name, phone, id_card, store_id, room_id, check_in_date, contract_end, rent_due_date, deposit, rent, status, **check_out_date**, attachments(JSON), created_at | 租户档案 + 租期；`status=active/left` |
| `payments` | id, no, tenant_id, tenant_name, store_id, room_no, amount, paid_at, remark, **rent_amount, utility_mode, water_mode, electricity_mode, rent_old_due, rent_new_due**, water_reading/usage/price/fee, electricity_reading/usage/price/fee, created_at | 收款单；`amount = rent_amount + water_fee + electricity_fee`；`utility_mode` 为兼容旧数据保留 |
| `reminders` | id, tenant_id, tenant_name, store_name, room_no, type, content, status, created_at | 站内提醒；`status=unread/read` |
| `audit_logs` | id, ts, actor_id, actor_name, actor_role, action, module, target_id, target_label, method, path, ip, user_agent, status, status_code, detail(JSON), request_id | **只追加**的操作日志；索引建在 `ts` / `(module,target_id)` / `actor_id` / `action` |

关系：`stores 1—N rooms`；`rooms 1—N tenants`；`tenants 1—N payments`；`payments.room_no` 与 `audit_logs.target_label` 均为**冗余快照字符串**（不外键关联，业务记录删除后日志仍可追溯）。数据库为 better-sqlite3 单文件，建表后所有新增列通过**幂等 `addCol` 迁移**补齐；`audit_logs` 用 `CREATE TABLE IF NOT EXISTS` 随启动自动建表，老库无需手工迁移。

## 6. 关键业务规则（实现口径）

| 规则 | 口径 |
| ---- | ---- |
| 计费方式 | 水、电**各自独立**：`''` 不计 / `meter` 按抄表 / `flat` 包月；允许混合 |
| 按抄表费用 | `max(0, 本次读数 − 房间当前读数) × 单价`；单价手填优先，否则取门店单价 |
| 读数推进 | 仅推进选「抄表」的项；`meter_date` 更新为收款日 |
| 收款金额 | `amount = 房租 + 水费 + 电费`，四舍五入到分 |
| 收款单号 | `SF` + 6 位递增（如 `SF000006`） |
| 房租顺延 | `max(本期到期日, 今天) + 1 个自然月`；**月末夹取**（2026-01-31 → 2026-02-28），全程纯字符串计算，与时区无关 |
| 到期状态口径 | 已超期 / **7 天内** / 正常（前后端统计卡与列表标签一致） |
| 时间 | 统一北京时间 `UTC+8`（服务器为 UTC 时按 +8h 取分量）；`paid_at` 完整到时分秒 |
| 房态联动 | `syncRoomStatus`：有 active 租户 → `rented`；原 `rented` 且无人 → `empty`；`maintenance` 保留；**`cleaning` 由退房直接写入，不参与自动回退** |
| 退房 | 记录 `check_out_date`，房间转 `cleaning`，在住人清空 |
| 操作日志 | 一次请求一条；写操作与敏感读（附件 / 导出 / 登录）默认记录，普通列表 GET 可配置；只追加、不可手动删除 |

## 7. 技术方案（实际）

| 层 | 选型 |
| ---- | ---- |
| 前端 | Vue 3 + Vite 4；桌面 **Ant Design Vue 4**，移动 **Vant 4**；共用 Pinia / vue-router / axios 封装 / API 模块 |

| 部署 | PVE LXC 容器+ nginx 静态托管 `dist` + 反代 `/api`；HTML 入口 `no-cache`，`/assets` 缓存 7 天；本地 `npm run build` 后经 `bash deploy.sh` 同步并 reload。脚本幂等生成随机 `JWT_SECRET`（`.env` 权限 600）、把 `CORS_ORIGINS=*` 收敛为留空、并排除同步 `server/.env` |

**v1.1 已加固的部署配置**：
- `deploy.sh` 首次部署自动生成 32 字节随机 `JWT_SECRET` 写入 `server/.env`（`chmod 600`），后续部署幂等不覆盖；同步时排除 `server/.env`，不会用本机配置冲掉容器凭据。

> 审计的边界：日志能回答「谁在何时改了什么」，但**不能阻止误操作**（防误操作靠详情二次确认、软删除与权限）；账号共用时只能追到账号而非自然人；单机 SQLite 下 admin 仍可通过整体恢复备份把日志带回旧时点，故属于**内部辅助追溯**而非不可抵赖的法律级审计。

  10. **v1.2 专项**：以非 admin 账号登录 → 菜单无「操作日志」，直接访问 `/api/audit/logs` 返回 403；收费账单操作列只有「查看详情」，点开后删除按钮在详情内且有两级提醒。
